## 변경 이유
- PR #109 원격 `CI`의 `release:verify`가 P0-02 독립 브랜치에서 legacy/hybrid 배치를 사용자 경로에 다시 노출하지 않는 계약과 기존 fixture 기대값 사이의 충돌로 실패했습니다.
- user-facing v3 거래 경로가 global legacy transaction store를 직접 읽거나 병합하지 않도록 static guard를 강화했습니다.
- same-id legacy/stored 공존 데이터는 자동 배정하지 않고 `MIGRATION_CONFLICT`로 quarantine해야 하므로 account binding command 표면을 저장소 소유 기준으로 좁혔습니다.

## 핵심 변경
- batch list/detail/cashflow/draft 계열 조회를 stored-first user-facing policy로 정리하고, 명시적 legacy fallback만 테스트 fixture에서 유지했습니다.
- `/api/planning/v3/transactions/batches/merge`는 legacy merge 실행 대신 `410 UNSUPPORTED`를 반환합니다.
- account binding은 stored meta 단독 배치만 갱신하고, same-id legacy 공존 배치는 `409 MIGRATION_CONFLICT`로 거부합니다.
- `hasLegacyBatch`를 추가해 legacy 내용을 읽어 노출하지 않고 존재 여부만 command guard 판단에 사용합니다.
- profile draft snapshot은 canonical CSV import 경로의 rule coverage 결과로 갱신했습니다.
