## 변경 이유
- replace restore가 손상 entry 또는 commit 중 write fault를 만났을 때 live 데이터를 일부 삭제한 뒤 성공처럼 보이면 안 됩니다.
- P0-03 기준은 replace restore를 원자적으로 처리해 미커밋 상태를 `RESTORE_NOT_COMMITTED`로 돌리고, snapshot/journal rollback 증거를 남기는 것입니다.
- ops safety script는 CI/로컬에서 같은 tsx import 경로로 동작해야 합니다.

## 핵심 변경
- replace restore 시작 전 hard-error preflight를 수행하고, commit 전 live snapshot과 `restore-replace-journal.json`을 작성합니다.
- commit 중 issue 또는 fault injection이 발생하면 snapshot rollback 후 `committed:false` summary를 반환합니다.
- restore route service는 `committed:false`를 `409 RESTORE_NOT_COMMITTED`로 매핑하고 audit/metric을 실패로 기록합니다.
- 다음 restore 진입 시 pending replace journal이 남아 있으면 rollback을 먼저 시도합니다.
- ops safety 실행 스크립트의 tsx import 방식을 `node --import tsx` 표준 경로로 정리했습니다.
