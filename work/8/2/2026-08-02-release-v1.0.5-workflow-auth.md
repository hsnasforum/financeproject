## 변경 이유

- `v1.0.5` 태그로 실행된 Release 워크플로 `30729849653`이 `Validate tag source and clean inputs` 단계에서 실패했습니다.
- 두 checkout 단계가 `persist-credentials: false`여서 private 저장소의 `git fetch`와 `git ls-remote`가 GitHub 인증 정보를 사용할 수 없었습니다.
- 실제 오류는 `fatal: could not read Username for 'https://github.com': No such device or address`였습니다.

## 핵심 변경

- 검증 job과 게시 job의 `actions/checkout`에 `persist-credentials: true`를 적용했습니다.
- 두 job에서 인증 유지 설정이 빠지면 실패하도록 Release 워크플로 계약 테스트를 보강했습니다.
- 기존 job별 최소 권한(`contents: read`, `contents: write`)은 그대로 유지하고 권한 범위를 넓히지 않았습니다.
- Release 검증과 게시 절차를 우회하거나 수동 게시하지 않습니다.

- GitHub CI 및 E2E Smoke는 PR을 푸시한 뒤 확인합니다.

## 남은 리스크

- 기존 원격 `v1.0.5` 태그는 실패한 워크플로 정의가 포함된 병합 SHA를 가리키고 있습니다.
- 태그 워크플로는 태그가 가리키는 커밋의 정의를 사용하므로, 수정 PR 병합만으로 기존 실행을 복구할 수 없습니다.
- GitHub Release는 아직 생성되지 않았으며 수동 게시로 우회하지 않습니다.
