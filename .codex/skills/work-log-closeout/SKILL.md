# Work Log Closeout

Create one work/<month>/<day>/YYYY-MM-DD-<slug>.md note for the milestone.

Use only observed facts:
- changed files
- skills actually used, or 없음
- why the change was needed
- concise core changes
- exact commands actually run and their outcomes
- unexecuted checks and residual risks
- optional non-blocking next round

Recommended headings:
변경 파일, 사용 skill, 변경 이유, 핵심 변경, 검증, 남은 리스크, and when useful 다음 라운드.

Do not claim unrun tests, live data, install, release, or external publication as complete. Keep retries and internal handoffs inside the same milestone note.
