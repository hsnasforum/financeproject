## 근거와 표현 경계

- IMAGE_01은 당시 로컬 commit의 실제 과거 보고서 8개 행과 `fresh=0`, `stale=8`을 사용했다. 원래 객체는 현재 원격에서 도달할 수 없지만 같은 수치와 행은 추적 가능한 commit `3cd889e9211079f350c97b2a8b2661fbf8c8a9fd`의 보고서에서 확인할 수 있다.
- IMAGE_02의 원본 터미널 출력은 보존돼 있지 않다. 서로 다른 실행을 하나의 연속 로그처럼 꾸미지 않고 2026-06-23 `/work` 기록을 시각화했다.
- IMAGE_03은 `main`의 `finlife:sync:if-stale` 실행 경로만 설명한다. 확인된 조건은 생성 시각 누락, 잘못된 시각, TTL 초과, 완료율 95% 미만의 네 가지다.
- IMAGE_04의 `fresh=8`은 날짜 기준 판정만 증명한다. 데이터 내용의 유효성이나 완전성까지 증명하지 않는다.
- IMAGE_05는 실제 `.data/exchange_snapshot.json`에서 `generatedAt`, `asOf`, `rowCount` 세 필드만 발췌했다.
- IMAGE_06은 현재 실제 화면에 세 상태가 동시에 나타난 장면이 아니다. `DataSourceStatusCard.tsx`의 `badgeLabel`과 `userSummary` 매핑을 정리한 코드 근거 이미지다.
- `configured/missing/error`는 연결 설정 상태이고, `live/cache/mock/degraded`는 응답 출처·품질을 나타내는 별도 체계다.

## 캡처 및 검수

- 2026-07-15 당시 로컬 캡처 작업은 과거 보고서 8개 행, 복구 보고서 8개 행, 환율 스냅샷 세 값, FINLIFE 6종, 조건부 갱신 네 조건과 UI 상태 문구가 근거 파일과 다르면 PNG 생성 전에 실패하도록 구성했다.
- 당시 생성 스크립트는 미추적 입력과 현재 도달할 수 없는 과거 commit에 의존해 재현 가능하지 않으므로 게시 대상에서 제외했다. 갱신 절차는 상위 `README.md`의 보관 정책을 따른다.
- `/settings/data-sources`를 로컬 개발 서버에서 Playwright로 열어 현재 화면 렌더링과 `연결 준비됨` 문구를 확인했다. 현재 환경에서는 카드가 모두 `연결 준비됨`이어서 세 상태 비교용 공개 이미지는 코드 매핑으로 유지했다.
- 6개 PNG 모두 1200×700 RGB이며 요소 overflow와 텍스트 clipping 검사를 통과했다.
- 저장 파일을 직접 열어 글자 잘림, 로딩 중 화면, 팝업, 불필요한 여백, 브라우저 UI와 민감정보 노출이 없음을 확인했다.
- 공개 이미지에 API 키, 토큰, 사용자명, 절대 경로, 내부 URL, 데이터베이스 정보와 env 이름을 넣지 않았다.

## 원고 반영 시 주의

- 현재 `main`의 `scripts/finlife_cli_common.mjs`에 있는 `runShouldSync`는 마지막 동기화 시도의 실패 여부를 직접 검사하지 않는다. 원고에서 현재 조건부 갱신 조건으로 이를 열거한 문장은 삭제하거나 다른 상태 판정 코드의 설명으로 분리해야 한다.
- 2026-07-15 실제 데이터 소스 설정 화면은 현재 환경에서 `연결 준비됨` 상태만 렌더링했다. “화면은 세 상태를 나눴다”는 문장은 실제 동시 표시가 아니라 화면 컴포넌트가 세 상태 문구를 지원한다는 의미로 쓰는 편이 정확하다.
